# Домашнє завдання № 5 — Алгоритми пошуку

**Автор:** Суровикін Олександр Сергійович.

Порівняння реалізацій алгоритмів Боєра–Мура, Кнута–Морріса–Пратта
та Рабіна–Карпа на двох статтях. Для кожного тексту виконано пошук наявного
та вигаданого підрядків. Усі наведені нижче значення отримано реальним запуском
`main.py` за допомогою `timeit.repeat`.

## Склад проєкту

- `main.py` — три алгоритми, перевірки правильності та вимірювання часу.
- `article_1.txt`, `article_2.txt` — повні тексти статей у UTF-8.
- `benchmark_results.json` — результати вимірювань, усі 7 серій для кожного
  випадку, параметри запуску, середовище та SHA-256 текстових файлів.
- `README.md` — методика, результати й висновки.
- `.gitignore` — виключення тимчасових файлів Python із репозиторію.

## Запуск

Потрібен **Python 3.10 або новіший**. Використано лише стандартну бібліотеку;
встановлювати сторонні пакети не потрібно. Команди виконуйте з папки проєкту:

```bash
python main.py
```

На Windows із налаштованим Python Launcher можна використати `py main.py`,
а в Linux/macOS — `python3 main.py`. Спочатку програма перевіряє правильність
алгоритмів, потім друкує час кожного випадку та переможців для текстів і загалом.
Статті завантажуються відносно розташування `main.py`, тому скрипт можна
викликати й з іншого робочого каталогу.

Лише перевірки правильності:

```bash
python main.py --check-only
```

Повторний експеримент зі збереженням результатів в окремий файл:

```bash
python main.py --number 200 --repeat 7 --output benchmark_results.local.json
```

Для наведеного звіту виконано ту саму команду з
`--output benchmark_results.json`. Звичайний запуск не змінює збережений звіт.
README містить результати зафіксованого запуску й не оновлюється автоматично.

Файли завантажено з Google Drive. Початкове кодування Windows-1251 перетворено
на UTF-8, завершення рядків — на LF. Зміст статей не змінено.
Довжина нижче — кількість символів Python `str`, включно з пробілами
та завершеннями рядків, а не кількість байтів.

| Текст | Файл | Символів | Байтів UTF-8 |
|---|---|---:|---:|
| Стаття 1 | `article_1.txt` | 12658 | 20823 |
| Стаття 2 | `article_2.txt` | 18400 | 31981 |

Обидва види підрядків мають **42 символи**. Наявні підрядки взято приблизно
із середини текстів. Індекс першого входження рахується від нуля:

| Текст | Наявний підрядок | Індекс |
|---|---|---:|
| Стаття 1 | `інтерполяції. Найефективніше застосовувати` | 6331 |
| Стаття 2 | `при традиційних представленнях структур не` | 9212 |

Вигаданий підрядок для обох текстів: `Цей вигаданий підрядок відсутній у статті.`
Перед вимірюванням програма перевіряє його відсутність. Очікуваний результат — `-1`.

## Реалізації та перевірка

- **Боєр–Мур:** порівняння справа наліво, таблиця останніх входжень символів
  і таблиця зсувів за правилом доброго суфікса.
- **Кнут–Морріс–Пратт:** префіксна таблиця дозволяє не повертатися назад
  по тексту після невідповідності.
- **Рабін–Карп:** ковзний поліноміальний хеш із основою 256 та модулем
  1 000 000 007. При збігу хешів обов'язково перевіряється сам підрядок,
  тому колізія не призводить до хибного результату.

Усі функції повертають індекс першого входження, `-1` для відсутнього
підрядка та `0` для порожнього. Вбудований `str.find` використовується
лише як еталон перевірки й для метаданих, поза вимірюваними функціями.

Кожний запуск виконує **3060 перевірок**: крайові випадки,
повторювані символи, Unicode, спеціально підібрану колізію хеша,
1000 відтворюваних випадкових пар і 4 випадки з реальними статтями.
Під час підготовки додатково пройдено 96 579 перевірок усіх пар двійкових
рядків довжини до 8 символів і зразків довжини до 5 символів.

## Методика вимірювання

- Середовище: **CPython 3.12.14**,
  `Windows-11-10.0.26200-SP0`.
- Процесор, як його повідомляє Python: `AMD64 Family 25 Model 97 Stepping 2, AuthenticAMD`.
- Час завершення вимірювань (UTC): `2026-11-07T10:27:59.157252+00:00`.
- Для кожної комбінації «стаття × підрядок × алгоритм» виконано
  3 прогрівальні виклики, потім **7 серій по 200 пошуків**.
- Вимірюється повний виклик функції, включно з побудовою таблиць
  або початкових хешів. Читання файлів, перевірки й друк виключено.
- Застосовано `timeit.repeat`. Як зазвичай у `timeit`, збирання сміття
  на час вимірювання тимчасово вимкнене. Порядок 12 комбінацій перемішано
  з фіксованим seed 5.
- Час серії поділено на 200. Основна метрика — **медіана** семи середніх
  часів одного пошуку; мінімум і максимум показують розкид між серіями.
  Мінімум також наведено як оцінку найкращого часу за найменшого впливу
  фонових процесів. Це не вимірювання кожного одиничного виклику окремо.
- Для підсумку за текстом підсумовано медіани двох сценаріїв; для загального
  підсумку — усіх чотирьох. Отже, кожен сценарій має однакову вагу.
  Це агрегат показників, а не окремий замір послідовного виконання.

## Висновки

1. **Для статті 1 найшвидший алгоритм — Боєр–Мур** в обох сценаріях.
   Сума медіан становить 191.803 мкс проти
   1245.395 мкс для КМП і
   3429.581 мкс для Рабіна–Карпа.
2. **Для статті 2 найшвидший також Боєр–Мур** в обох сценаріях:
   315.709 мкс сумарно проти
   1757.429 мкс для КМП і
   5302.924 мкс для Рабіна–Карпа.
3. **Загальний переможець — Боєр–Мур**: 507.511 мкс.
   За сумою чотирьох медіан він приблизно у
   5.92 раза швидший за КМП та у
   17.21 раза — за Рабіна–Карпа.
   Ранжування зберігається, якщо порівнювати мінімуми серій.
4. На цих даних Боєр–Мур виграє завдяки можливості зміщувати зразок
   одразу на кілька позицій. КМП послідовно переглядає текст, а реалізація
   Рабіна–Карпа в Python додатково виконує модульну арифметику для кожного вікна.
   Це пояснення узгоджується із замірами, але кількість порівнянь тут окремо
   не вимірювалася.
5. Пошук відсутнього підрядка повільніший в усіх випадках: потрібно
   перевірити текст до кінця, тоді як наявний зразок знаходиться приблизно
   посередині. Для другої, довшої статті час також більший, хоча на нього
   впливають і вміст тексту, і конкретний зразок.
6. Висновок стосується **цих реалізацій, двох текстів і вибраних підрядків**.
   Інші довжини зразків, повторюваність символів, розташування збігу,
   версія Python та навантаження комп'ютера можуть змінити результати.
   Експеримент не доводить універсальної переваги одного алгоритму.
